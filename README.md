# بوابة مرشحي أفضل 100 جامعة — دليل النشر (GitHub Pages + Firebase)

الموقع صفحة واحدة ثابتة (`index.html`) تقرأ بيانات المرشحين من قاعدة **Cloud Firestore**،
ويدخل المسؤول إلى لوحة التحكم بحساب **Firebase Authentication**. كل الخدمات المستخدمة ضمن الخطة المجانية (Spark).

## محتويات المجلد

| الملف | الغرض |
|---|---|
| `index.html` | البوابة كاملة: لوحة التحليلات، مستكشف الإحصاءات، البحث المتقدم، الجامعات، لوحة التحكم |
| `firebase-config.js` | إعدادات مشروعك في Firebase (تعدّله مرة واحدة) |
| `firestore.rules` | قواعد الحماية: القراءة للجميع والكتابة للمسؤولين فقط |
| `data/candidates.json` | البيانات الأولية (419 مرشحاً) تُستورد بضغطة زر من لوحة التحكم |
| `.nojekyll` | يمنع GitHub Pages من معالجة الملفات |

---

## الخطوة 1: إنشاء مشروع Firebase
1. افتح https://console.firebase.google.com واضغط **Add project**، وسمِّ المشروع (مثلاً `top100-portal`). يمكنك إيقاف Google Analytics.
2. من القائمة: **Build ← Firestore Database ← Create database** واختر الوضع **Production** وموقعاً قريباً (مثل `europe-west` أو `me-central`).
3. من القائمة: **Build ← Authentication ← Get started ← Sign-in method** وفعّل **Email/Password**.

## الخطوة 2: إنشاء حساب المسؤول
1. في **Authentication ← Users** اضغط **Add user** وأدخل بريدك وكلمة مرور قوية.
2. انسخ قيمة **User UID** التي تظهر بجانب الحساب.
3. في **Firestore Database ← Data** اضغط **Start collection** وسمِّها `admins`.
   - **Document ID**: الصق الـ UID الذي نسخته.
   - أضف حقلاً واحداً، مثلاً `role` = `admin`، ثم احفظ.

> لإضافة مسؤول آخر لاحقاً: أنشئ له حساباً في Authentication ثم مستنداً جديداً في `admins` باسم معرّفه.

## الخطوة 3: نشر قواعد الحماية
في **Firestore Database ← Rules** احذف المحتوى الموجود، والصق محتوى ملف `firestore.rules` كاملاً، ثم اضغط **Publish**.

## الخطوة 4: ربط الموقع بالمشروع
1. في **Project settings (رمز الترس) ← General ← Your apps** اضغط رمز الويب `</>` وسجّل تطبيقاً باسم البوابة (دون Firebase Hosting).
2. انسخ القيم من كائن `firebaseConfig` الظاهر، والصقها في ملف `firebase-config.js` مكان `YOUR_...`.

## الخطوة 5: النشر على GitHub Pages
1. أنشئ مستودعاً جديداً على GitHub (عاماً، مثل `top100-portal`).
2. ارفع **كل** محتويات هذا المجلد إلى جذر المستودع (بما فيها مجلد `data` وملف `.nojekyll`).
   - من المتصفح: **Add file ← Upload files** واسحب الملفات.
3. من **Settings ← Pages**: اختر **Deploy from a branch**، والفرع `main` والمجلد `/ (root)`، ثم **Save**.
4. بعد دقيقة أو دقيقتين يظهر رابط الموقع: `https://<اسم-المستخدم>.github.io/top100-portal/`.

## الخطوة 6: السماح للنطاق بتسجيل الدخول
في **Authentication ← Settings ← Authorized domains** اضغط **Add domain** وأضف `<اسم-المستخدم>.github.io`.

## الخطوة 7: استيراد البيانات الأولية
1. افتح الموقع، ثم تبويب **لوحة التحكم**، وسجّل الدخول بحساب المسؤول.
2. سيظهر شريط «قاعدة البيانات فارغة»، فاضغط **استيراد البيانات الأولية**.
3. تظهر الرسوم والإحصاءات فوراً لكل الزوار.

## الاستخدام اليومي
- **إضافة مرشح**: لوحة التحكم ← النموذج. اختيار الجامعة من القائمة يملأ الدولة والترتيب تلقائياً.
- **تعديل أو حذف**: جدول «إدارة المرشحين» أو من نافذة المرشح في البحث المتقدم.
- **نسخة احتياطية**: زر «تنزيل نسخة احتياطية» في أعلى لوحة التحكم (ملف JSON بكل المرشحين). يُنصح بها أسبوعياً.
- **تصدير نتائج البحث**: زر «تصدير النتائج CSV» في صفحة البحث المتقدم (يفتح في Excel مع دعم العربية).

## حدود الخطة المجانية
- يُخزَّن المرشحون في مستندات مجمّعة (250 مرشحاً في كل مستند)، لذا تكلّف زيارة الموقع **مستندين أو ثلاثة فقط** من حصة القراءة اليومية (50,000).
- حجم المستند الواحد في Firestore حتى 1 ميجابايت، وهذا يتسع لآلاف المرشحين.

## الأمان
- قيم `firebase-config.js` ليست أسراراً، ومن الطبيعي أن تظهر في الموقع.
- الحماية الفعلية في `firestore.rules`: لا يستطيع أي زائر التعديل إلا إذا كان مسجّلاً ومعرّفه موجوداً في مجموعة `admins`.
- **تنبيه بالخصوصية**: الموقع العام يعرض أسماء المرشحين وروابط LinkedIn لأي زائر. إذا كانت البيانات داخلية، فاجعل القراءة للمسجّلين فقط بتغيير السطر `allow read: if true;` إلى `allow read: if request.auth != null;` وأنشئ حسابات للمستخدمين المصرّح لهم.
